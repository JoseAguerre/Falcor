# Sampling cost on a smaller GPU (supplementary material)

Repeats two of the paper's GPU benchmarks on this machine, an **NVIDIA GeForce RTX 4050 Laptop GPU
(6 GB, 35 W)** in an ASUS ROG Flow Z13, to answer the question the paper leaves open in
Section *Leaf budget*: *"All these measurements are on one GPU; we could not test a GPU with a
smaller cache."*

Nothing in `paper/`, `paper-revised/` or `paper-experiments/` is modified. All output of this study
lives in this directory.

## What is measured

| Phase | Mode | What it gives |
|---|---|---|
| `chase` | `QuadLightSamplerBench` `BENCH_MODE=chase` | Latency of dependent random reads against working set, 4 KB .. 512 MB. Exposes the L1 and L2 capacities of this GPU. |
| `sampler` | `BENCH_MODE=sampler` | GPU time of the isolated light-sampling dispatch, per sampler and leaf budget. Directly comparable with Table 2 of `paper-revised/newtests/ablation-leaf-number`. |
| `gpubuild` | `BENCH_MODE=gpubuild` | Cost of the 2D CDF build passes; also records the emitter resolution, which verifies that the scenes loaded the intended textures. |

## Protocol

Identical to the paper's, so that the numbers can be compared directly:

* `1440x1440` threads with 128 light samples each. `1440^2 = 2073600 = 1920x1080`, so this is exactly
  the paper's "one 1920x1080 frame at 128 light samples per pixel".
* Pointer chase with `512x512` threads of 128 hops, 70 frames.
* One separate process per configuration, so that no GPU clock state can favour one configuration.
* The median over frames inside a process, then the median over rounds.

One deliberate deviation: **seven rounds instead of three.** The clock of this GPU is not lockable
(`nvidia-smi -lgc` is refused without administrator rights) and the part is power limited to 35 W, so
single runs scatter by up to 40%, in both directions, depending on the boost and thermal state. A
repeatability probe (`probe_variance.py`) showed that medians over five or more rounds are stable to
about 2% while single runs are not; the spread across rounds is reported alongside every number.

## Scenes

The emitter textures of three of the paper's five scenes survive on this machine, as renamed copies
under `paper-experiments/figures_only_comparison_grid/`. They are restored to the paths the
`.pyscene` files expect (`quadlight/`, which is git-ignored) and are **byte-identical to the content
the paper measured**, so the comparison is exact rather than approximate:

| Scene | Emitter texture | Resolution |
|---|---|---|
| Phone | `quadlight/colors/frame_00987.hdr` | 1920x1080 |
| Fireplace | `quadlight/fireplace/4k/frame_00082.hdr` | 3840x2160 |
| Convergence | `quadlight/cave/frame_00221.hdr` | 3840x2160 |

Rover and Cinema are **not** reproducible here: their emitter videos are not on this machine, which
is also why the paper's LED-wall resolution test could not be repeated.

## Running it

```sh
python run_bench.py chase   --rounds 3
python run_bench.py sampler --rounds 7
python run_bench.py gpubuild --rounds 3
python analyze.py                        # tables/, figures/, data/summary.json
```

`run_bench.py` skips configurations whose result JSON already exists, so an interrupted sweep can be
resumed. `analyze.py` needs `numpy` and `matplotlib`.

The `QuadLightSamplerBench` plugin is not in the prebuilt binaries in `build/`; build it with the
CMake that configured the build tree (packman's 3.24.1, **not** a newer CMake on `PATH`, which fails
to reconfigure it):

```sh
"C:/packman-repo/chk/cmake/3.24.1+nv3-windows-x86_64/bin/cmake.exe" \
    --build build/windows-vs2022 --config Release --target QuadLightSamplerBench Mogwai
```

## Output

* `note.tex` / `note.pdf` — the three-page supplementary note.
* `tables/table_cost.tex` — the main comparison table, used by the note.
* `tables/table_chase_body.tex` — the pointer-chase numbers; generated, but **not** used by the
  note, which plots the same data in `fig_chase` instead.
* `figures/fig_chase.pdf`, `fig_budget.pdf` — used by the note.
* `figures/fig_cost.pdf` — ns per light sample against structure size, this GPU against the paper's.
  Generated and correct, but left out of the note for space: `table_cost.tex` carries the same data
  with more precision. Worth including if the note is ever allowed a fourth page.
* `data/*.json` — one raw result per configuration, plus `summary.json`.
* `probe_variance.py` — the repeatability probe that set the number of rounds.

All tables and figures are regenerated by `analyze.py`; do not edit them by hand. Rebuild the note
with `pdflatex note.tex` (run it twice so the cross-references resolve); on this machine pdflatex is
at `C:\Users\Elojo\AppData\Local\Programs\MiKTeX\miktex\bin\x64\`, not on `PATH`.

Every number attributed to the RTX 4080 SUPER is **quoted from the paper**, not re-measured; the
sources are named in `analyze.py` next to the values.
